카페의 주문 데이터를 열었다고 해보자. 주문 금액이 비어 있는 행이 있고, 같은 주문이 두 번 들어 있고, 평소보다 훨씬 큰 결제도 하나 보인다. 전처리 함수를 배우다 보면 빈칸은 채우고 큰 값은 지우는 식으로 손이 먼저 움직이기 쉽다.

그런데 처리할 때마다 질문이 생긴다. 빈칸에 0을 넣어도 될까? 큰 결제는 단체 주문일 수도 있지 않을까? 평균은 어느 데이터로 계산해야 할까?

이번 글에서는 값의 뜻을 확인하고, 학습 데이터에서 정한 기준을 새 데이터에 적용하는 순서를 따라간다. 마지막에는 숫자 여섯 개로 결측치 대체와 스케일링을 직접 확인한다.

1. 먼저, 한 행이 무엇인지 알아야 한다

Missing value(결측치), Duplicate(중복), Outlier(이상치)를 찾기 전에 데이터의 단위를 확인한다. 카페 데이터라면 한 행이 주문 한 건인지, 하루 매출인지부터 알아야 한다. 주문 금액의 단위도 원인지 천 원인지 확인한다.

같은 고객이 같은 음료를 두 번 주문했다면 두 건 모두 유효하다. 같은 주문 번호가 수집 과정에서 두 번 저장됐다면 중복을 의심할 수 있다. 중복 판단은 한 행의 의미와 고유 키에서 시작한다. 원본을 남겨두고 작업용 복사본에서 처리하면 바뀐 결과를 비교하기도 쉽다.

발견한 값 먼저 확인할 것 가능한 처리
비어 있는 주문 금액 무료 주문인가, 수집 실패인가? 원자료 확인, 대체, 결측 표시
같은 주문 번호 두 개 같은 사건이 두 번 저장됐는가? 중복 수집이 확인되면 하나로 정리
평소의 100배인 금액 단위 오류인가, 실제 단체 주문인가? 오류 수정 또는 값 유지

표는 판단의 출발점이다. 삭제나 대체 방법은 데이터의 의미와 분석 목적에 맞춰 정한다.

2. 빈칸을 채우기 전에 데이터를 나눈다

일부 전처리는 데이터에서 기준을 배운다. 빈칸을 채울 중앙값, 표준화에 쓸 평균과 표준편차, 숫자 범위를 바꿀 최솟값과 최댓값이 여기에 해당한다.

기준은 Train set(학습 세트)에서만 계산한다. Validation set(검증 세트)과 Test set(테스트 세트)에는 학습 때 정한 기준을 적용한다. 테스트까지 합쳐 평균을 구하면, 평가에 쓸 데이터의 정보가 학습 과정에 들어간다. 이를 Data leakage(데이터 누출)라고 한다. scikit-learn의 데이터 누출 설명

파일의 열 이름과 단위, 수집 오류를 확인하는 작업은 앞에서 할 수 있다. 데이터의 분포에서 대체값이나 경계를 구할 때는 분할을 먼저 한다. 같은 사람의 기록이 여러 행이라면 사람 단위 분할을, 미래를 예측하는 문제라면 시간순 분할을 검토한다.

3. 결측치에는 사정이 있다

카페의 휴무일 매출 0원과 수집에 실패한 매출 빈칸은 뜻이 다르다. 모든 빈칸을 0으로 채우면 두 상황이 같은 값으로 남는다.

수치형 열에는 평균이나 Median(중앙값)을 대체값으로 사용할 수 있다. 중앙값은 소수의 큰 값에 비교적 덜 흔들린다. 다만 모든 고객의 빈칸을 하나의 값으로 채우면 고객 집단마다 다른 특성을 충분히 반영하기 어렵다. 필요하면 ‘원래 비어 있었는지’를 표시하는 열을 함께 만든다. 결측치 대체 방법

예를 들어 학습 값이 10, 20, 빈칸, 30이라면 관측된 값의 중앙값은 20이다. 이 기준으로 빈칸을 채우면 10, 20, 20, 30이 된다. 나중에 들어온 테스트 데이터의 빈칸에도 학습 때 구한 20을 넣는다.

시간 데이터는 특히 예측 시점을 생각해야 한다. 나중에 보고서를 완성할 때는 다음 달 값을 참고해 빈칸을 보간할 수도 있다. 이번 달에 다음 달을 예측하는 모델이라면, 아직 모르는 다음 달 값을 전처리에 사용할 수 없다.

4. 이상치는 확인할 후보로 남긴다

매일 10만 원 안팎이던 매출에 1,000만 원이 나타났다고 하자. 입력 실수일 수도 있고 큰 행사가 있었을 수도 있다. 원자료, 단위, 날짜를 함께 확인해야 판단할 수 있다.

IQR(사분위 범위)은 가운데 50%가 차지하는 폭이다. 흔히 Q1 − 1.5 × IQR보다 작거나 Q3 + 1.5 × IQR보다 큰 값을 확인 대상으로 고른다. 이 경계를 넘었다는 사실만으로 입력 오류가 확정되지는 않는다.

데이터에서 이상치 경계를 계산해 모델 입력을 바꾸기로 했다면, 그 경계도 학습 데이터에서 정한다. 테스트 점수를 확인한 뒤 점수를 떨어뜨리는 행만 골라 지우면 평가 대상이 달라진다. 어떤 행을 왜 바꿨는지 기록해두는 이유다.

5. 스케일링은 숫자의 기준을 맞춘다

하루 방문 횟수가 1~5, 구매 금액이 1,000~100,000인 데이터를 떠올려보자. 거리를 이용하는 모델에서는 숫자 범위가 큰 열이 계산에 큰 영향을 줄 수 있다. Feature scaling(특성 스케일링)은 열마다 다른 숫자 크기를 조정하는 작업이다. 필요한 변환은 모델과 데이터에 따라 고른다.

방법 학습 데이터에서 구할 기준 알아둘 점
StandardScaler 평균·표준편차 중심과 크기를 조정한다. 정규분포를 만드는 기능은 없다.
MinMaxScaler 최솟값·최댓값 기본 설정에서는 학습 범위를 0~1로 옮긴다. 새 값은 이 범위를 벗어날 수 있다.

두 방법 모두 극단값의 영향을 받을 수 있다. 스케일링을 했다고 이상치가 사라지는 것도 아니다. StandardScaler · MinMaxScaler

학습 최솟값이 10, 최댓값이 30이라면 Min-Max 변환은 아래와 같다.

변환값 = (입력값 − 10) / (30 − 10)

10 → 0.0
20 → 0.5
30 → 1.0
40 → 1.5

새로 들어온 40은 학습 범위보다 크므로 1.5로 변환된다. 여기서는 기본 설정인 clip=False를 사용한다. 0~1은 학습 데이터가 정한 범위라는 점을 기억하면 결과를 읽기 쉽다.

입력값을 바꿔도 학습 최솟값 10과 최댓값 30은 그대로다. clip=False 기준.

6. 숫자 여섯 개로 직접 실행해보기

아래 예제는 설명을 위해 새로 만든 작은 데이터다. 학습용 네 행과 테스트용 두 행을 미리 정했고, 각 행에는 숫자형 특성이 하나씩 있다. 실제 프로젝트에서는 문제에 맞는 분할을 먼저 수행한다.

Pipeline(파이프라인)으로 중앙값 대체와 스케일링을 차례로 연결한다. 이 실습으로 전처리 결과를 확인한다. 예측 모델을 학습하거나 성능을 측정하는 단계는 포함하지 않는다.

import numpy as np
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import MinMaxScaler

# 각 행은 표본 하나, 각 열은 특성 하나다.
X_train = np.array([[10], [20], [np.nan], [30]], dtype=float)
X_test = np.array([[40], [np.nan]], dtype=float)

preprocess = Pipeline([
    ("fill", SimpleImputer(strategy="median")),
    ("scale", MinMaxScaler()),
])

train_ready = preprocess.fit_transform(X_train)
test_ready = preprocess.transform(X_test)

print("Train:", train_ready.ravel().tolist())
print("Test:", test_ready.ravel().tolist())
print("중앙값:", preprocess.named_steps["fill"].statistics_[0])
print("학습 최솟값·최댓값:",
      preprocess.named_steps["scale"].data_min_[0],
      preprocess.named_steps["scale"].data_max_[0])

예제 파일 내려받기

실행 결과는 다음과 같다.

Train: [0.0, 0.5, 0.5, 1.0]
Test: [1.5, 0.5]
중앙값: 20.0
학습 최솟값·최댓값: 10.0 30.0

fit_transform(X_train)은 학습 데이터에서 중앙값과 범위를 구하고 값을 바꾼다. transform(X_test)는 이미 구한 기준을 적용한다. 테스트의 40 때문에 학습 최댓값이 40으로 바뀌지 않는다. 테스트의 빈칸에도 같은 중앙값 20이 들어간다.

숫자 열과 문자 열에 서로 다른 처리를 적용하려면 ColumnTransformer(열별 변환기)를 함께 사용할 수 있다. 변환을 묶어두면 새 데이터에도 학습한 순서 그대로 적용하기 편하다. Pipeline 사용법

7. 문자 범주와 구간도 같은 원칙을 따른다

‘매장’, ‘배달’, ‘포장’처럼 순서가 없는 값에는 One-hot encoding(원핫 인코딩)을 사용할 수 있다. 학습 데이터에서 범주 목록을 정하고, 테스트에도 같은 열 구성을 적용한다. 새로운 범주가 들어올 때의 처리도 미리 정한다. 예를 들어 OneHotEncoder(handle_unknown="ignore")는 학습에서 보지 못한 범주에 해당하는 열 묶음을 모두 0으로 표현한다. OneHotEncoder

연속값을 구간으로 나누는 Binning(구간화)도 마찬가지다. 분위수처럼 데이터에서 구간 경계를 계산한다면 학습 데이터에서 정한다. 테스트를 별도로 나눠 경계를 다시 계산하면 같은 숫자가 서로 다른 구간 이름을 얻을 수 있다.

8. 책을 덮고 두 가지만 설명해보기

테스트 데이터의 빈칸을 테스트 중앙값으로 채우면 왜 문제가 될까?

테스트 분포로 새로운 기준을 만들면 평가 데이터의 정보가 변환 규칙에 반영된다. 학습 데이터에서 구한 대체값을 그대로 적용해야, 학습한 처리 방법이 새로운 데이터에서도 어떻게 작동하는지 확인할 수 있다.

MinMaxScaler를 거친 값이 1.5라면 무엇부터 확인할까?

새 값이 학습 최댓값보다 큰지 확인한다. 학습 범위가 10~30이고 입력이 40이면 기본 설정에서 결과는 1.5다. 이 값은 입력이 학습 범위를 얼마나 벗어났는지 보여준다.

전처리를 마치면 처리 전후의 행 수, 남은 결측치, 열 이름과 자료형을 확인한다. 무엇을 지웠는지, 어떤 값으로 채웠는지, 그 기준을 어느 데이터에서 구했는지 설명할 수 있으면 다음 학습 단계로 넘어갈 준비가 된다.

이 글과 음성에 대해

AIFFEL 수업을 공부하며 만든 개인 학습 노트를 공개용으로 다시 구성했다. 글의 숫자 예제는 설명을 위해 별도로 만들었으며, 강의 원문이나 실습 결과를 옮긴 자료가 아니다. 함께 실은 선히 TTS(음성 합성) 음성은 기존 전처리 복습 대본으로, 보간·이상치·인코딩·구간화까지 더 넓게 다룬다.
